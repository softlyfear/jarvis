Для поиска используй доступные Hugging Face model_search, hub_repo_details с README и paper_search; проверь первичные репозитории разработчиков. Сохраняй запросы, ID и ревизии моделей, язык, лицензию, параметры, режим потоковой генерации, зависимости и фактически подтверждённое железо. Отдельно отмечай ограничения Windows и AMD. Авторский benchmark не выдавай за результат на видеокарте пользователя.

Корпус: `.codex/scenarios/voice-corpus.json`. Он включает числа, пути, отрицания, вопросы, короткие и длинные ответы. У всех TTS-кандидатов одинаковый образец Jarvis New и точный текст образца; для ASR нужны одни и те же WAV и эталонные расшифровки. Не меняй штатный синтезатор только по популярности модели.

Для готового локального сервера с протоколом Jarvis `/health` и `/tts` используй `python3 .codex/tools/benchmark_voice.py --help`. Сервер должен сообщить согласованные профиль, GPU и устройство синтеза. Проверка сохраняет полный WAV, время HTTP-ответа, длительность звука, RTF и отдельный прогрев. Происхождение `observed_http` подтверждает HTTP-измерение; модель/образец остаются заявленными, GPU отдельно не удостоверен (`hardware_verified: false`). Фикстуры тестов имеют происхождение `fixture`. Время первого байта HTTP не называется временем первого слышимого звука. Настоящая потоковая генерация требует отдельного адаптера и измерения первого воспроизводимого аудиоблока.

Потребление VRAM, сходство голоса, ошибки произношения и субъективное качество измеряй отдельно с сохранением метода; если измерения отсутствуют, пиши «не измерено». Новые зависимости сначала проверяй изолированно от работающего голосового сервера. Стоимость и облачные jobs требуют отдельной авторизации; обычный поиск и чтение карточек её не требуют.

Результат: таблица кандидатов, источник каждого заявленного преимущества, измеренные/неизвестные показатели, выбор следующего теста и условия замены. Подключение этого навыка не означает разрешения автоматически менять модели пользователю.
