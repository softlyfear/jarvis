# Модели речи для Jarvis: исследование на 5 октября 2026

Первый кандидат для уменьшения задержки — **MOSS-TTS-Nano-100M с ONNX**. Для качества клона следует сравнить **VoxCPM2** и **Qwen3-TTS Base**. Для распознавания интересны **Parakeet v3 / Nemotron 3.5 через NeMo-Speech.cpp** и **GigaAM-v3**. Это порядок испытаний, а не подтверждённая замена установленного F5: новые модели на Windows/RX 7900 XTX здесь не запускались.

## Как проводился поиск

Через настоящий официальный Hugging Face MCP выполнено 38 запросов `hub_repo_search`: TTS/ASR по загрузкам, популярности и новизне, русский язык, 25 семейств моделей и последние публикации пяти разработчиков. Основная выдача содержит 476 разных ID. Дополнительно через `hf_fs` выполнены три поиска моделей, два поиска статей и чтение двух карточек; объединённая выдача содержит 491 уникальный ID. Затем проверены метаданные 45 существующих репозиториев, 42 полные карточки на закреплённых ревизиях и первичные репозитории разработчиков. Точные запросы, результаты, ревизии, хеши и ограничения сохранены в [машинном отчёте](voice-models-2026-10-05.json).

Старые инструменты HF App `model_search`/`hf_doc_fetch` в этой сессии возвращали «Tool not found». Использован действующий сервер `https://huggingface.co/mcp`, версия 0.4.28. Поиск был анонимным; ответы 429 пережидались, три закрытые карточки с 401 не считаются прочитанными. Примеры и числа ниже взяты из первичных источников; загружаемые в поиск ID не означают запуск каждой модели. Образец вашего голоса на внешние сервисы не отправлялся.

## Что уже работает у вас

Архив 5 октября относится к Jarvis 0.2.63, build `6ee6d2`, AMD RX 7900 XTX. Текущий STT — whisper.cpp, `large-v3-turbo` q8, Vulkan. Текущий TTS — ESpeech RL-V2/F5, 16 шагов, RUAccent, образец Jarvis New до 12 секунд. Подробный разбор — [отчёт по логам](../reviews/2026-10-05-documents-voice-development.md).

## Windows/AMD и зависимости

Нашёл два полезных направления. [NVIDIA NeMo-Speech.cpp](https://github.com/NVIDIA/NeMo-Speech.cpp) документирует поддерживаемые ASR, Windows и Vulkan, поставляет установку и GGUF-модели. Его опубликованные 2,3 мс на RTX 4090 / 27 мс на CPU относятся к чанку **другого, английского Nemotron Speech Streaming 0.6B**; они не доказывают скорость русского Nemotron 3.5. [Инструкция сборки](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/main/docs/build.md).

[audio.cpp](https://github.com/0xShug0/audio.cpp) объединяет много семейств ASR/TTS и документирует Windows/Vulkan, CPU, CUDA, Metal и HIP. Но автор прямо предупреждает о преимущественной оптимизации CUDA и различиях покрытия других backend. Поддержка runtime в целом не означает успешный русский клон каждой модели на AMD; потоковые возможности также различаются по модели. [Windows-сборка](https://github.com/0xShug0/audio.cpp/blob/main/docs/build/windows.md). Это перспективный отдельный адаптер, а не уже включённая возможность установщика Jarvis.

Для Nano официальный ONNX-инференс может работать без PyTorch, однако обычный `pip install -e .` по текущему `pyproject.toml` всё равно тянет `torch==2.7.0`, `torchaudio==2.7.0`, Transformers 4.57.1. Нужен отдельный минимальный ONNX-пакет и проверка обоих кодеков; официальный скрипт показывает CPU/CUDA provider, DirectML/ROCm этим источником не подтверждены. [Зависимости](https://github.com/OpenMOSS/MOSS-TTS-Nano/blob/main/pyproject.toml), [инференс](https://github.com/OpenMOSS/MOSS-TTS-Nano/blob/main/infer_onnx.py).

VoxCPM2 добавляет `torchcodec`, Gradio 6 и другие пакеты, которые нельзя без проверки подмешивать в работающий F5. Qwen TTS сейчас закрепляет **Transformers 4.57.3**; требование Transformers 5 относится к **Qwen ASR HF**, а не ко всему семейству. RUAccent в текущем Jarvis требует `<5`. FlashAttention 2 в Qwen TTS рекомендован, но не объявлен обязательным. [VoxCPM dependencies](https://github.com/OpenBMB/VoxCPM/blob/main/pyproject.toml), [Qwen TTS dependencies](https://github.com/QwenLM/Qwen3-TTS/blob/main/pyproject.toml).

## Что даст уменьшение задержки

В `crates/jarvis-core/src/tts.rs` клиент сначала читает `resp.bytes()`, получает весь WAV, сохраняет его и только затем начинает воспроизведение. Даже модель с быстрым первым чанком не даст пользователю этот выигрыш при нынешнем пути. Нужны потоковый транспорт, воспроизведение PCM по мере поступления, защита от разрывов и сохранение barge-in/блокировки микрофона. А для поступления текста от LLM порциями понадобится отдельная интеграция её потока.

Текущий универсальный установщик выбирает оборудование для существующей пары Whisper/F5. Он не обеспечивает совместимость произвольной новой модели. CPU-TTS Nano означал бы новое решение продукта; действующий запрет автоматического CPU-фолбэка F5 сохранён. Исследование не меняет штатный сервер или модель пользователя.

## Конкретный следующий эксперимент

Порядок: **F5 baseline → Nano ONNX → VoxCPM2 → Qwen Base 0.6B/1.7B**. ASR отдельно: **Whisper baseline → Parakeet/NeMo-Speech.cpp → GigaAM-v3 → Nemotron 3.5**. Вторая очередь нужна только если первая не даст нужного сочетания качества и скорости.

План испытаний сохранён в [voice-trials-2026-10-05.json](voice-trials-2026-10-05.json), статус `proposed_not_run`. Использовать один точный образец Jarvis New, локальные WAV и корпус минимум из 50 фраз с именами, путями, числами, вопросами, отрицаниями и ударениями. Начальный корпус из девяти фраз уже есть в `.codex/scenarios/voice-corpus.json`; он не выдаётся за готовый большой benchmark.

Измерять отдельно холодную загрузку, прогретые p50/p95, полную генерацию, RTF, первый воспроизводимый PCM и слышимый старт, VRAM/RAM, повторяемость и прерывание речи. Показатель RTF меньше 1 означает генерацию быстрее длительности аудио; он не гарантирует быстрый старт. Для сравнения клона — сохранённые WAV и слепое A/B-прослушивание, произношение и WER на одном русскоязычном распознавателе. Исходные аудио остаются локальными.

Предлагаемый порог замены: не менее **25% уменьшения p50 и p95 начала воспроизведения** относительно свежего F5 на том же ПК, без ухудшения сходства/произношения и без поломки прерывания, установки и перезапуска. Цели 300 мс p50 / 500 мс p95 для первого аудио — ориентир эксперимента, не установленный результат. Для ASR важнее отсутствие ошибок «открой/закрой» и «не сохранять/сохранить», чем несколько выигранных миллисекунд. Окончательный выбор голоса принимает пользователь по прослушиванию; модель по одному рейтингу автоматически не переключается.
