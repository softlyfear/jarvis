# Саморевью интеграции OpenClaw — 05.10.2026

Ниже сохранены результаты прежнего ревью 0.2.59. После дополнительного поручения пользователя программный остаток завершён: создан и проверен настоящий профиль OpenClaw, добавлены установка, каталог моделей, Control UI, ранний синтез и отмена HTTP. Аппаратную приёмку на Windows выполняет пользователь по своему указанию.

## Найденные дефекты и исправления

1. **P1 — MCP-задание могло пережить отменённый голосовой запрос.** В мосте создавался независимый токен; после выхода HTTP-потока `mcp_blocked()` уже не блокировал его очередь. Регрессионный тест на настоящем локальном HTTP воспроизвёл выполнение `system_info` после отмены. Теперь принятый MCP-вызов хранит дочерний токен активного запроса, и отмена действует после удаления запроса из RUNNING. Таймаут отдельного MCP-вызова не отменяет родителя.
2. **P1 — автоматический Direct fallback мог повторить уже начатую задачу.** Отсутствие клиентских tool reports не доказывает, что OpenClaw не вызывал внутренние MCP или внешние инструменты. POST 401/404 также не доказывает отказ до начала задачи: это могут быть ошибки провайдера. Теперь fallback допускается только при ошибке установления соединения. Вызовы локальных инструментов учитываются в общем счётчике родителя/MCP; если их итог потерян, возвращается ResultUnknown с просьбой проверить результат. Регрессии: внутреннее действие перед 401/404/503; отсутствие повтора при 401/403/404/405/408/5xx.
3. **P1 — проверка отмены и запуск Action не были сериализованы между потоками.** Общий замок теперь охватывает проверку токена и запуск; тот же замок используют нативные голосовые действия, подтверждённое выполнение и ответы диалогов. Тест проверяет отмену запроса, ожидающего этот замок: Action не запускается, счётчик остаётся нулевым. Уже начатую операцию отмена не откатывает.
4. **P2 — некорректный MCP-запрос мог вызвать действие.** Отсутствующий, null, объектный или дробный ID попадал в tools/call; пустой ответ моста и некорректное изображение могли помечаться успешными. Теперь ID/JSON-RPC/params проверяются до вызова; некорректные результаты помечаются isError. Регрессии исключают исполнение запроса с неправильным ID и проверяют пустые/ошибочные payload.
5. **P2 — непригодный итог модели терял известный результат действий.** Пустой ответ или только код после успешного tool приводили к InvalidResponse без отчёта о выполненном. Для английских рассуждений OpenClaw не применял фильтр Direct. Теперь сохраняется фактический отчёт действий, а reasoning не озвучивается. Тесты: пустой ответ, блок кода, английские рассуждения после tool.
6. **P2 — ответ с неправильной ролью или типом tool мог попасть в executor.** Добавлена проверка role=assistant, type=function, уникальных непустых ID и формы tool_calls для обычного и собранного SSE-ответа. Неправильный ответ до действий не исполняется; после действий ошибка возвращается вместе с известными отчётами.

Сверены [OpenClaw HTTP API](https://docs.openclaw.ai/gateway/openai-http-api) и [MCP 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic). Первая документация описывает provider failures с 401/404; вторая требует строковый/целочисленный ненулевой request ID. Состояние документации проверено 05.10.2026.

## Ограничения, которые остаются

MCP stdio не передаёт идентификатор голосовой задачи. Привязка принятых вызовов выполняется к активному запросу Jarvis. Новый вызов, пришедший после завершения его worker, невозможно надёжно отнести к отменённой задаче. Внешние инструменты и подагенты OpenClaw также отменяются самим Gateway. Это нельзя выдавать за полную отмену всей удалённой задачи.

Настоящий Gateway установлен в изолированном `.codex/.tmp/` и проверен с тестовым провайдером. Микрофон, GPU/F5, платную модель, Windows-действия и личные внешние аккаунты принимает пользователь по `docs/OPENCLAW-RU.md`.

## Ревью завершения

1. Профиль прошёл проверку настоящей схемы OpenClaw 2026.9.8. Повторная настройка сохраняет память, persona, токен и внешние MCP. Устаревшие `agents.list`/`memorySearch` не используются.
2. **Найден и исправлен P1:** клиентский `web_search` конфликтовал со встроенным инструментом и ломал настоящий запрос Gateway. HTTP-каталог теперь имеет префикс `jarvis_client__`; MCP и Direct не меняются. Сквозной Rust-тест выполняет настоящий безопасный `timers` Action и возвращает агенту фактический результат.
3. Ограничения помощников проверены Gateway: нет shell, Windows/MCP-инструментов и дальнейшего делегирования. `jarvis-vision` вообще не имеет инструментов.
4. **Исправлено:** синхронный HTTP оставлял зависший worker до таймаута. Async response отбрасывается при отмене; тесты проверяют закрытие сокета при зависших заголовках и SSE. Gateway прекращает upstream-запрос без fallback-повтора.
5. Ранний TTS синтезирует одно законченное предложение. Воспроизведение допускается после совпадения с очищенным итоговым ответом; отмена, ошибка или другой итог отбрасывают заготовку.
6. **Исправлено:** camelCase `apiKey` и MCP Authorization не покрывались прежним экспортом секретов. Экспорт учитывает приватный профиль; при отсутствующем/нечитаемом профиле журналы скрываются. Одноразовая ссылка Control UI не проходит через общий журнал URL.
7. Optional installer прошёл PowerShell parser и mock-download тесты: готовая среда, корректная SHA256 и отказ неверной SHA256. Пользовательская память сохраняется.
8. Linux: 182 теста ядра; реальный Gateway contract запускается отдельно. Frontend test/build/check, Playwright и Windows app/GUI/test cross-check пройдены. Настоящий Gateway включён в CI Linux/Windows. MSVC-сборка, установщик и выпуск проверяются CI точного опубликованного SHA; его итог приводится в итоговом ответе.
9. **Исправлено при дополнительной проверке:** заглушка `keyless` передавалась как Bearer и отклонялась Kilo с `INVALID_TOKEN`. Для бесплатного режима используется поддерживаемое значение `anonymous`, старые ключи игнорируются. Проверен ответ настоящего Kilo на заведомо несуществующую модель без выполнения платной генерации: `keyless` даёт 401, `anonymous` и отсутствие заголовка проходят авторизацию и дают 404 модели. В Gateway-тест добавлена проверка фактического заголовка отдельного провайдера без ключа. [Правила анонимного доступа Kilo](https://kilo.ai/docs/gateway/authentication).

Программные пункты 16, 20–22, 29–31 и optional installer закрыты в выбранной архитектуре. Для Claude CLI и личного внешнего сервиса пользователь выполняет установку/вход. Аппаратная приёмка раздела 39 передана ему.
