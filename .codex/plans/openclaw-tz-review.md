## Вывод

Направление подходит текущей архитектуре. Быстрые локальные команды остаются в Jarvis; Direct остаётся самостоятельным режимом; OpenClaw получает разговор и агентные задачи. Существующие Windows Actions, F5-TTS и голосовые подтверждения переиспользуются.

Главная ожидаемая польза — контекст, память и задачи с несколькими шагами. Качество распознавания речи и синтеза само подключение OpenClaw не улучшает. Качество планирования зависит также от выбранной модели и настройки агента.

## Проверенный HTTP-контракт

Источник: https://docs.openclaw.ai/gateway/openai-http-api

- `/v1/chat/completions` поддерживает клиентские function tools и возврат `tool_calls`; результаты передаются как `role: tool` с соответствующим `tool_call_id`.
- Endpoint выключен по умолчанию: требуется `gateway.http.endpoints.chatCompletions.enabled = true`.
- `model: "openclaw/jarvis"` выбирает агента. Это не идентификатор модели провайдера. Без отдельного override используется модель, настроенная у агента.
- Для сохранения диалога нужен постоянный `user` для конкретной беседы либо явно заданный ключ сессии. Без этого каждый запрос получает новую сессию.
- Gateway token — отдельный секрет подключения; это не ключ Polza/Kilo.
- Перечень `/v1/models` содержит цели агентов, поэтому будущий выбор моделей нельзя строить на предположении, что это каталог моделей провайдера.

Источник: https://docs.openclaw.ai/gateway/health

- `/healthz` подтверждает, что HTTP-сервер жив; это не проверка доступности выбранной модели и всего пути выполнения.
- Кнопка проверки подключения должна различать доступность процесса, готовность Gateway, авторизацию и доступность нужного HTTP endpoint/агента. Сам health check не доказывает работоспособность LLM.

## Что уже есть в коде

- `llm.rs`: ротация провайдеров и ключей, cooldown, пять раундов tools, общий бюджет запроса до 60 секунд, локальная история, `remember_command`, обработка результатов уже выполненных действий.
- `llm/tools.rs`: схемы инструментов и `to_action`; их можно переиспользовать.
- `actions.rs::Action::run`: вход через проверку опасного действия и голосовое подтверждение. Новый backend и MCP должны вызывать этот путь, а не напрямую `execute`.
- `app.rs::ask_llm`: синхронный вызов `llm::handle`. `wait_for_wake_word` вызывается при озвучке. Слушатель прерывания текущего HTTP-запроса пока отсутствует.
- `assistant_config.rs`: секции `agent` пока нет; Direct должен оставаться значением по умолчанию для старых конфигов.

## Уточнения до реализации

1. **Переход на резервный движок после действия.** Если OpenClaw уже открыл программу, напечатал текст или создал заметку, нельзя повторить исходную задачу целиком через Direct. Нужно вернуть известные результаты; автоматический fallback безопасно начинать до побочных эффектов. При timeout неизвестен также результат внутренних действий OpenClaw — такой случай требует отдельной политики, а не слепого повторения.
2. **Подтверждение как продолжение tool call.** Нужны backend/session/request/tool-call ID и состояние ожидания подтверждения. Вопрос «Удалить?» — не успешный результат удаления. После «да», «нет», ошибки или истечения ожидания агент должен получить действительный результат. Сейчас подтверждённое действие выполняется отдельной веткой `app.rs`, а LLM-цикл заканчивается на вопросе.
3. **Отмена во время запроса.** Для обещанного игнорирования устаревшего ответа нужен идентификатор поколения запроса и слушатель активации во время ожидания. Проверять отмену нужно перед каждым новым действием и перед озвучкой. Сетевая отмена не отменяет уже выполненные действия.
4. **Единый владелец контекста.** OpenClaw хранит основной диалог; Jarvis — сессию, очередь событий локальных команд и состояние текущих вызовов. Определить порядок доставки событий, повторную отправку и поведение при переключении на Direct. Передавать локальные события можно вместе со следующим агентным запросом, не добавляя задержку к простой команде.
5. **Политика инструментов самого OpenClaw.** Проверки Rust контролируют только вызовы Jarvis tools. Если у агента есть собственный shell или файловые инструменты с доступом к этому ПК, они могут обойти эти проверки. Для агента `jarvis` необходимо отдельно ограничить такие возможности; одного системного промпта недостаточно.
6. **Очистка ответа для голоса.** `clean_for_speech` удаляет маркеры Markdown, reasoning и ограничивает длину, но не исключает содержимое code fences и длинные URL. Это отдельный пробел относительно пункта 15 ТЗ.
7. **Настройки и секреты.** Использовать единые названия `connect_timeout_secs` и `request_timeout_secs`, устранить расхождение с ранним `timeout_secs`. Добавить маскирование произвольного Gateway token: текущий `mask_secrets` ориентируется на `keys` и известные префиксы API-ключей. Не расширять маскирование только за счёт одного ожидаемого формата нового токена.
8. **Предел агентной задачи.** Не переносить жёстко пять Direct-раундов в OpenClaw, но сохранить явные бюджет времени, отмену и ограничение количества внешних действий. Отдельно различать обычный ответ и длительную задачу.
9. **Проверка настоящего Gateway.** Моки полезны для логики Jarvis, но не доказывают совместимость с OpenClaw. Зафиксировать поддерживаемую версию и выполнить контрактную проверку текста, tools, продолжения сессии и авторизации с настоящим Gateway. Действия Windows и звук дополнительно проверяются на Windows.

## Порядок реализации

1. Закрепить HTTP-контракт и правила сессии, отмены, подтверждения и fallback после побочных эффектов.
2. Ввести `AgentRequest`, `AgentReply`, `AgentError` и возможность выдавать события; обернуть существующий Direct без изменения поведения. Общий исполнитель tools оставить единым.
3. Добавить необязательную секцию `[agent]`, OpenClaw HTTP-адаптер, отдельные таймауты, идентификатор беседы, события локальных команд и восстановление после недоступности.
4. Добавить GUI: «Напрямую / OpenClaw», адрес, агент, защищённый ввод токена, проверка подключения и понятные состояния ошибки. Модель первой версии определяется конфигурацией OpenClaw.
5. Проверить сценарий «открой блокнот → напечатай привет → готово», отказ действия, подтверждение/отмену, отсутствие повторных действий при fallback, старый конфиг и прерывание устаревшего ответа.
6. После стабильной первой версии — MCP-адаптер к работающему `jarvis-app`, vision, долговременная память, streaming и внешние интеграции. Hermes оставить точкой расширения, без реализации на первом этапе.
