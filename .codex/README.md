# Инструкции GPT/Codex для jarvis

Главный файл — [AGENTS.md](AGENTS.md). Все проектные правила GPT, настройки,
навыки, хуки и служебные файлы находятся в `.codex/`. `.claude/` и `CLAUDE.md`
для GPT доступны только на чтение. Исходный код остаётся общим.

## Как загружаются правила

В доверенном проекте Codex читает `.codex/config.toml`. Поле
`developer_instructions` требует перед работой полностью прочитать
`.codex/AGENTS.md`; этот файл является единственным источником основных правил.
Стандартный обход `AGENTS.md` из корня не заходит в дочернюю `.codex/`, поэтому
корневой файл или симлинк не создаётся. `model_instructions_file` не используется:
оно заменяет встроенные инструкции модели, а здесь требуется их дополнение.

Навыки указаны в `skills.config` и доступны для автоматического выбора.
На Codex CLI 0.159.2 каталог четырёх навыков и инструкция загрузки проверены
через `codex debug prompt-input` без запуска модели.
Относительные пути настроек вычисляются от `.codex/config.toml`.
Логи и SQLite-состояние направлены в `.codex/logs/` и `.codex/state/`.
Глобальный профиль, учётные данные и внешние плагины установки Codex этим
переносом не изменяются и не копируются в репозиторий.

Если другой клиент не поддерживает проектный `config.toml`, дать ему стартовую
инструкцию: «Прочитай `.codex/AGENTS.md` полностью и следуй ему для всего
репозитория». Для этой сессии пользователь уже явно задал эти правила.

## Хуки и ограничения

Codex требует доверия к проекту и каждому определению хука. При следующем
запуске `/hooks` показывает определения и позволяет доверить их штатным способом.
Доверие не подделывается, автоматический запуск в текущей сессии не обещается.
Скрипты рассчитаны на Linux, WSL или окружение с Bash, Git, Python 3.10+ и `rg`.

Проверка окружения ничего не устанавливает:

```bash
bash .codex/hooks/session-start.sh
```

При авторизованной установке можно отдельно запустить тот же скрипт с
`--install`. Он добавляет Windows target и rust-analyzer через существующий
rustup; пакеты apt ставятся только при запуске администратором. Сам хук не
вызывает sudo, не скачивает отдельный профиль агента и не пишет в переменные
окружения Claude. `DOCS_RS=1` задаётся конфигурацией или непосредственно командой.

Решение `ask` из Claude guard не поддерживается хуками Codex. Вместо него
возвращается `deny` с причиной и требованием конкретной авторизации.
Защита shell и путей эвристическая: произвольные программы, вложенные оболочки,
сложные переменные и все возможные способы записи она не анализирует.
Правила владения из `AGENTS.md` обязательны независимо от работы хуков.
Запрет GPT на запись в `.claude/` не меняет поведение Claude: пользователь
задаёт Claude встречное правило о неприкосновенности `.codex/`.

```bash
python3 -m unittest discover -s .codex/tests -v
bash -n .codex/hooks/session-start.sh
```

Внутренние временные результаты, кеши, журналы и состояние исключаются
`.codex/.gitignore`. Проверки приложения не нужны для изменения только
агентских инструкций и скриптов.
