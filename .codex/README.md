# Инструкции GPT/Codex для jarvis

Главный файл — [AGENTS.md](AGENTS.md). Все проектные инструкции, настройки,
навыки, хуки, память и служебные файлы Codex находятся только в `.codex/`.

- `.codex/config.toml` — загрузка инструкций и настройки проекта.
- `.codex/hooks.json` — определения хуков; подготовка Linux проверяет окружение,
  а shell guard защищает от опасных команд и удаления корней проекта и системы.
- `.codex/skills/` — проектные навыки, включая сборку Windows и проверку GUI.
- `.codex/.cache/`, `.codex/.tmp/` — локальные кеши и временные результаты.

Сборочный навык использует `gh run list` / `gh run view` либо доступный GitHub MCP.
Проверки приложения: `npm test`, `npm run build`, `npm run check` и команды Rust,
указанные в `AGENTS.md`; устаревшие обходы проверок не применять.

## Как загружаются правила

В доверенном проекте Codex читает `.codex/config.toml`. Поле
`developer_instructions` требует перед работой полностью прочитать
`.codex/AGENTS.md`; этот файл является единственным источником основных правил.
Стандартный обход `AGENTS.md` из корня не заходит в дочернюю `.codex/`, поэтому
корневой файл или симлинк не создаётся. `model_instructions_file` не используется:
оно заменяет встроенные инструкции модели, а здесь требуется их дополнение.

Навыки указаны в `skills.config` и доступны для автоматического выбора.
На Codex CLI 0.159.2 каталог четырёх навыков и инструкция загрузки проверены
через `codex debug prompt-input` без запуска модели.
Относительные пути настроек вычисляются от `.codex/config.toml`.
Логи и SQLite-состояние направлены в `.codex/logs/` и `.codex/state/`.
Глобальный профиль, учётные данные и внешние плагины установки Codex этим
переносом не изменяются и не копируются в репозиторий.

## Проверка результата и независимое ревью

Для реализации поведения и интеграций правила требуют независимого reviewer:
роль в `agents/reviewer.toml`, регистрация в `config.toml`. Агент работает на
чтение и проверяет требования, фактический diff и артефакты; основной агент
устраняет существенные находки. Это разрешённый пользователем процесс.

Новые навыки `review-logs` и `benchmark-voice` зарегистрированы в проектной
конфигурации. Первый разбирает ZIP без распаковки, отделяет версии/сессии и
маскирует ключи. Второй использует Hugging Face и общий корпус, а его скрипт
измеряет настоящий локальный HTTP/WAV-путь без выдуманных показателей качества.

```bash
python3 -m unittest discover -s .codex/tests -v
python3 .codex/tools/review_logs.py ARCHIVE.zip --date 2026-10-05 --version 0.2.63 --output .codex/.tmp/log-review.json
python3 .codex/tools/check_scenarios.py --trace .codex/scenarios/observed-2026-10-05.json
python3 .codex/tools/check_evidence.py .codex/plans/development-2026-10-05/requirements.json --require-complete
python3 .codex/tools/benchmark_voice.py --help
```

Сценарная реконструкция известных ошибок возвращает код 1, пока ошибки
присутствуют. Зелёные unit-тесты означают, что валидатор обнаруживает эти ошибки;
они не означают их исправления или проверки Windows на настоящем ПК.
Трасса `observed` требует источника и SHA256; фикстура никогда не закрывает
аппаратную приёмку. Формат описан в `scenarios/README.md`.

В списке требований каждый проверенный пункт ссылается на артефакт и проверенные
исходники с SHA256. Изменённый исходник требует повторной проверки. Если осталось
требуемое испытание на реальном железе, статус — `hardware_pending`.

Если другой клиент не поддерживает проектный `config.toml`, дать ему стартовую
инструкцию: «Прочитай `.codex/AGENTS.md` полностью и следуй ему для всего
репозитория». Для этой сессии пользователь уже явно задал эти правила.

## Инструменты MCP

Настроены Serena для чтения символов/связей и Playwright для проверки браузера.
Установка, проверка, ограничения и уже подключённые Apps описаны в
[mcp/README.md](mcp/README.md). Все локальные кеши размещены внутри `.codex/`.

## Хуки и ограничения

Codex требует доверия к проекту и каждому определению хука. При следующем
запуске `/hooks` показывает определения и позволяет доверить их штатным способом.
Доверие не подделывается, автоматический запуск в текущей сессии не обещается.
Скрипты рассчитаны на Linux, WSL или окружение с Bash, Git, Python 3.10+ и `rg`.

Проверка окружения ничего не устанавливает:

```bash
bash .codex/hooks/session-start.sh
```

При авторизованной установке можно отдельно запустить тот же скрипт с
`--install`. Он добавляет Windows target и rust-analyzer через существующий
rustup; пакеты apt ставятся только при запуске администратором. Сам хук не
вызывает sudo, не скачивает отдельный профиль агента и не меняет глобальное окружение. `DOCS_RS=1` задаётся конфигурацией или непосредственно командой.

Решение `ask` не поддерживается хуками Codex. Вместо него
возвращается `deny` с причиной и требованием конкретной авторизации.
Защита shell и путей эвристическая: произвольные программы, вложенные оболочки,
сложные переменные и все возможные способы записи она не анализирует.
Правила из `AGENTS.md` обязательны независимо от работы хуков.

## Проверки переноса

```bash
python3 -m unittest discover -s .codex/tests -v
bash -n .codex/hooks/session-start.sh
```

Внутренние временные результаты, кеши, журналы и состояние исключаются
`.codex/.gitignore`. Проверки приложения не нужны для изменения только
агентских инструкций и скриптов.
