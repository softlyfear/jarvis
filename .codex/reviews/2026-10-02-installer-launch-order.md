# Ранний запуск после обновления 0.2.54

Симптом пользователя: GUI 0.2.54 уже открыт, установщик остаётся на странице голосового сервера с `[server] download finished`; затем оба закрываются. Новых журналов в Telegram Desktop нет; причина проверена по коду проекта и исходникам Inno Setup.

Обычные `[Run]` выполняются в `Setup.MainForm.Install.ProcessRunEntries` до `SetStep(ssPostInstall, True)`. Два тихих запуска app/GUI имели `nowait`, но не `postinstall`. В `ssPostInstall` Jarvis ещё настраивал голос, затем повторно вызывал StopJarvis и закрывал уже запущенные новые exe. После него повторного запуска не было.

Исправление: обе записи тихого запуска получили `postinstall`. Сохранён порядок «остановить старые процессы → скопировать файлы → сохранить настройки → обновить голосовой сервер → завершить оставшиеся процессы → запустить app/GUI». Обычная установка сохраняет прежние флажки запуска на завершающей странице.

Добавлен `installer/tests/lifecycle.Tests.ps1`. Он компилирует настоящий `jarvis.iss` с маленькими тестовыми exe, заменяя только настройку и голосовой runtime на маркеры/задержку. Ярлыки и автозапуск исключены из тестовой поставки, установка не регистрируется для удаления. Проверяются запуск после настройки и сохранение обоих процессов через две секунды после выхода установщика, сначала без Python, затем при работающих старых app/GUI и существующем runtime. Проверка включена в Windows CI перед публикацией. Модели и пакеты не скачиваются.

Локально пройдены parser PowerShell, BOM/CRLF, тесты фильтрации/остановки процессов и миграции runtime. Реальная компиляция и выполнение Inno Setup проверяются в Windows CI после пуша. GUI и ядро не изменялись.

Официальные источники: https://jrsoftware.org/ishelp/topic_runsection.htm , https://jrsoftware.org/ishelp/topic_scriptevents.htm , https://github.com/jrsoftware/issrc/blob/main/Projects/Src/Setup.MainForm.pas .
