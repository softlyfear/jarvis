## Подтверждено

- Фото показывает два окна 0.2.40. В 09:38:55.158 и 09:38:55.272 трей вызвал запуск GUI дважды. GUI стартовали в 09:38:55.456 и 09:38:55.530. Проверка заголовка окна выполнялась до создания первого окна и пропустила обе копии. Оба клиента подключились к IPC.
- Обновление с 0.2.38 на 0.2.40 было запущено в 09:27:21. Новая версия стартовала в 09:27:32, но в 09:27:34 не смогла занять порт IPC 9712: Windows error 10048. После этого окно многократно получало ошибки IPC. Кто держал порт, по архиву однозначно не установить: PID владельца и `update-install.log` отсутствуют. Оставшийся или перезапущенный старый процесс — возможная причина, не доказанный факт.
- В 09:33:42 и 09:34:21 нейросеть дала текст ответа; HTTP TTS оба раза вышел по таймауту 30 с и перешёл к SAPI. Ошибки SAPI в журнале нет, слышимость системного голоса архивом не подтверждается.
- `voice-server.log`: Whisper large-v3-turbo/Vulkan на RX 7900 XTX загрузился. F5 отсутствовал (`No module named 'f5_tts'`); XTTS увидел маркер предыдущего сбоя GPU и выбрал CPU. После загрузки 25 образцов при старте первый запрос remaster снова клонировал эти же 25 образцов. POST /tts до конца сохранённого лога не завершился, STT и /health отвечали.
- `voice-update.log` показывает успешную установку F5 1.1.22 в private Python, загрузку моделей и завершение обновления runtime. При этом голосовой лог не имеет времени/интерпретатора запуска и ранее затирался перезапуском. Нельзя установить, относится ли отсутствие F5 к запуску до завершения миграции, к другому окружению или к сохранившейся копии сервера.
- Видео длится 39:49. Проверены выборочные кадры начала и поздних участков. Это прежняя сессия (пользователь отдельно уточнил), по ней не оценивались новые правки шумоподавления или качество нового F5. Аудио целиком не прослушивалось.
- Получен настоящий текст заметок: браузеры/приложения, команды без активного окна, шум и акценты, контекст, несколько мониторов, календарь/напоминания, фоновая работа, естественный диалог. Это общие пожелания; реализация всего списка не входила в исправление текущего сбоя.

## Изменения

- GUI держит системную файловую блокировку в каталоге пользовательских настроек ещё до инициализации окна. При одновременном запуске второй процесс ожидает появления первого окна и выводит его вперёд. Файл не удаляется; блокировка снимается при завершении процесса.
- Установщик останавливает окно, ассистент и серверы текущей установки в этом порядке. Повторно перечисляет процессы до трёх пустых проверок, ловит запоздало появившихся детей, ждёт завершения и отказывает в продолжении, если процесс выжил. После миграции runtime повторяет остановку перед [Run], чтобы официальный запуск не использовал сервер, открытый во время миграции.
- XTTS использует уже прогретые латенты, если выбранный пак содержит ровно те же образцы, что startup voice. Другие паки по-прежнему клонируются и кешируются отдельно. Это устраняет повторную подготовку remaster; не гарантирует укладывание CPU inference любого ответа в 30 с.
- Перезапуски голосового сервера дописывают лог с датой, версией, сборкой и путём Python. При превышении 10 МиБ предыдущий лог переносится в `voice-server.previous.log`, который входит в сбор логов.

## Проверки

- 129 Linux Rust unit tests: в том числе восемь одновременных попыток получить блокировку, повторный запуск после освобождения, сохранение и ротация журнала.
- 57 Python tests с mock models: повторное использование стартового клона и независимый кеш другого голоса.
- Парсер PowerShell, тест остановки процессов (выбор установки, порядок, задержка выхода, поздний ребёнок, устойчивый отказ), существующий тест миграции runtime — успешно.
- Windows GNU type check app/GUI — успешно. Существующие предупреждения компилятора не менялись.
- Inno Setup/MSVC, Windows tests и упаковку проверяет CI опубликованного коммита. Итог CI сообщается отдельно после завершения.
- Реальная повторная установка, отсутствие двух окон и озвучка F5 на RX 7900 XTX требуют проверки на Windows ПК пользователя.

API блокировки сверено с [документацией Rust](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock), запуск Tauri — через Context7 по документации Tauri 2. Новых зависимостей не добавлено.
