# Настройки Grok Build для jarvis

Главный файл общих правил — корневой [`AGENTS.md`](../AGENTS.md). Настройки Grok
находятся в `.grok/`. Общие процедуры, навыки, проверки, планы и доказательства
остаются в `.codex/` и не копируются.

- `.grok/config.toml` — разрешения и MCP, которые Grok читает из проекта.
  Остальные ключи Grok берёт только из `~/.grok/config.toml`.
- `.grok/rules/` — правила сессии и Git для Grok.
- `.grok/hooks/` — проверка окружения и защита shell. Команда записана целиком
  в поле `command`: Grok 1.0.70 отбрасывает отдельный массив `args` и тогда
  запускает только `bash` или `python3`. Проверка вызывает общий
  `.codex/hooks/session-start.sh` и ничего не устанавливает. Защита вызывает
  общий `.codex/hooks/guard-bash.py` и дополнительно закрывает каталог `.grok/`.
- `.grok/skills/` — короткие адаптеры к каноническим навыкам в `.codex/skills/`.
- `.grok/agents/reviewer.md` — определение независимого ревьюера.

`.codex/` этой настройкой не изменяется. Собственные файлы Grok имеют приоритет по
имени навыка.

## Загрузка

В доверенном каталоге Grok читает корневой `AGENTS.md`, затем `.grok/rules/*.md`.
Хуки проекта запускаются после доверия к каталогу (`/hooks-trust` или `--trust`).
Пока доверия нет, хук не считается выполненным.

Проверка окружения:

```bash
bash .grok/hooks/session-start.sh
```

Установка недостающих пакетов — отдельное действие:

```bash
bash .grok/hooks/session-start.sh --install
```

Скрипт передаёт аргументы общему `.codex/hooks/session-start.sh`. `DOCS_RS=1`
нужно задавать в командах `cargo check` и `cargo test`: проектный `config.toml`
Grok не умеет записывать переменные окружения shell.

## Разрешения

`.grok/config.toml` разрешает обычные команды разработки и запрещает
катастрофический `rm` корня системы, домашнего каталога и `.grok/`.
Префикс `rm -rf .codex` не запрещён: так очищается `.codex/.tmp`, а точечные
опасные формы ловит hook. Это не закрытый список: команда вне списка
спрашивает разрешение согласно режиму сессии.
Опасные формы по-прежнему разбирает hook. Grok умеет решение `ask`, поэтому
обёртка сохраняет его. Общий скрипт Codex превращает `ask` в `deny`, потому что
хук Codex не умеет спрашивать.

## MCP

Подключены серверы, которые уже установлены в общем кеше `.codex/.cache/`:

- Serena — чтение символов. Запуск идёт через `.codex/mcp/launch.py`.
  Проект Serena помечен `read_only`.
- Hugging Face Hub — поиск и карточки моделей, `https://huggingface.co/mcp`.
- Context7 — документация библиотек. Сайт `https://context7.com/`,
  сервер `https://mcp.context7.com/mcp`.

Playwright MCP не включён: проектный `config.toml` Grok не умеет
список разрешённых инструментов, а у сервера есть `browser_run_code_unsafe`.
Проверка окна остаётся у навыка `gui-check` и его скрипта.

Новый сеанс нужен, чтобы подхватить MCP и хуки. Установка отсутствующего
сервера: `python3 .codex/mcp/setup.py`.

## Проверки

```bash
python3 -m unittest discover -s .grok/tests -v
bash -n .grok/hooks/session-start.sh
```

Проверки приложения для правки только этих инструкций не требуются.
CI запускает тот же unittest на push в `master`.
